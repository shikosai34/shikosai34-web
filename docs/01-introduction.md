## 1.1 要件定義の目的

Issue #1 の ToDo に対応する。すなわち次の4点を記述する。

1. システム設計に登場するデータのうち、どれを公式Webサイト（以下、HP）で公開表示するのかの整理
2. 各ページとデータモデルの対応表の作成
3. 公開時に表示する項目・表示しない項目の確定
4. 上記を踏まえた要件の記述

あわせて、Figma によるデザイン作成とコーディングを開始する前に、**何を作るのか・どこまで作るのか・誰がいつまでに何を決めるのか** をチーム内で共通の記述として持つ。

## 1.2 注意事項

本文書に記載した内容は、Issue #1、添付のデザイントンマナ、第33回の実装から構成した草案である。そのため、いくつか修正の余地がある。

## 1.3 スコープ

この要件定義書では、以下の事項については取り扱わない。

- **体制・スケジュール・進行管理**（役割分担、担当者の割り当て、期限の設定。別途 Issue で管理する）
- **FesFlow の要件**（別途 FesFlow 側で定義する。本文書では HP との境界のみ扱う。第2.5節）
- パンフレット、ポスター、ステッカーなど印刷物のデザイン
- 当日運営のオペレーション
- 協賛営業・会計の業務フロー（HPへの掲載要件のみ扱う）

ただし、**設計上の制約となる運用事項は各章に含める。** 例として、サークル画像が任意提出であること（第2.9.3節）は、代替表示を用意する必要を生むため記述する。

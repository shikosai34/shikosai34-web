## 3.0 着手前に決めること

Figma 作業を止めうる事項を、決定が必要な時期の順に示す。**上2件は `03_Wireframe` に着手する前に決める必要がある。**

| # | 決めること | 影響する範囲 | 該当節 |
| --- | --- | --- | --- |
| 1 | ナビゲーションの階層構造（17ページの分類） | 全ページのヘッダー・フッター | 3.6 |
| 2 | slug の形式（サークルのURL） | `/circle/[slug]` のページ設計 | 第2.8.2節 |
| 3 | 装飾用3書体のライセンス | 見出しの表現方法 | 3.3 |
| 4 | FesFlow とフォントを共通にするか | 書体の選定 | 3.1、3.3 |
| 5 | 追加カラー（罫線・補助テキスト・注意喚起） | `01_Foundation` の登録内容 | 3.2.2 |
| 6 | サークル画像の縦横比 | `Card/Circle` の寸法 | 3.10 |

1〜2 が決まらない場合でも、`01_Foundation`（カラー・タイポグラフィ・グリッド）は本文書の記載値で着手できる。

## 3.1 デザインコンセプト

- テーマ「守破離」から、新しいものと古いものの融合として **「和風 × サイバーパンク」** をキーワードとする。
- 情報の混雑が起こりやすいテーマであるため、**グリッドを基準としたレイアウトを用い、情報量の中に余白を確保する。**

Web における具体化:

| 観点 | 方針 |
| --- | --- |
| 背景 | 濃紺（`#0B3041`）を基調とする暗い配色を全ページで維持する |
| 装飾 | 六角形パターン、縦のカラーバー、雲形をトンマナのスライド意匠から引用する |
| 発光表現 | ロゴと一部の見出しにネオンサイン風の表現（`text-shadow` / `box-shadow`）を用いる |
| 抑制 | 発光表現を本文には適用しない。可読性を優先する |

**HP と FesFlow のデザインは統一しない ［確定］。** 両者は役割の異なる別のシステムであり、それぞれの用途に合わせて設計する。ただし来場者は `/circle/[slug]` から FesFlow へ遷移するため、**遷移先が別システムであることが分かる導線を設ける**（第3.2.2節の6）。

**フォントの扱いは今後相談する ［要検討］。** デザイン全体を統一しない方針のもとで、書体だけを共通にするかどうかを FesFlow 側の担当者と調整する。

## 3.2 カラー

| 役割 | 色名 | HEX | Tailwind トークン名（案） |
| --- | --- | --- | --- |
| 背景・ベース | Sub color | `#0B3041` | `base` |
| 文字（標準） | White | `#E8E8E8` | `text` |
| 主要色 | Main color | `#FF9933` | `main` |
| 強調色 | Accent color | `#00FFCC` | `accent` |

### 3.2.1 コントラスト比の検証結果

WCAG 2.1 の相対輝度式に基づき算出した。新たな色を追加する場合は、Figma のコントラスト比プラグインまたはブラウザの開発者ツールで検証する。手計算は不要である。

| 前景 | 背景 | 比 | 本文（4.5:1） | 大きい文字（3:1） | 判定 |
| --- | --- | --- | --- | --- | --- |
| `#E8E8E8` | `#0B3041` | 11.33 | 適合 | 適合 | 本文に使用可 |
| `#00FFCC` | `#0B3041` | 10.69 | 適合 | 適合 | 使用可 |
| `#FF9933` | `#0B3041` | 6.51 | 適合 | 適合 | 使用可 |
| `#0B3041` | `#FF9933` | 6.51 | 適合 | 適合 | ボタン等に使用可 |
| `#0B3041` | `#00FFCC` | 10.69 | 適合 | 適合 | ボタン等に使用可 |
| `#E8E8E8` | `#FF9933` | 1.74 | 不適合 | 不適合 | **使用不可** |
| `#E8E8E8` | `#00FFCC` | 1.06 | 不適合 | 不適合 | **使用不可** |
| `#FF9933` | `#00FFCC` | 1.64 | 不適合 | 不適合 | **使用不可** |

### 3.2.2 運用ルール

1. **オレンジまたはミントを背景に使う場合、その上の文字色は必ず `#0B3041` とする。** 白（`#E8E8E8`）を載せると判読できない。
2. 本文テキストは `#E8E8E8` を `#0B3041` 上で使用する。
3. `#FF9933` と `#00FFCC` を隣接させて配置しない。両者の比は 1.64 で、境界が識別しにくい。区切る場合は間に背景色を挟む。
4. リンクテキストは `#00FFCC` を用い、下線を併用する。色のみで状態を区別しない。
5. トンマナに記載のとおり、Main color（`#FF9933`）はパンフレット・広報物での主要色である。Web では面積の大きい塗りではなく、ボタン・強調要素など限定的な範囲に用いる ［要検討］。
6. **FesFlow への遷移ボタンには専用の配色を割り当てる ［要検討］。** サイト内リンクと外部システムへの遷移が同じ見た目だと、来場者が遷移先を予期できない。

**［要検討］** 次の色は現在のパレットに存在しないため追加を検討する。

- 罫線・区切り線用の中間色（`#0B3041` を明るくした色）
- 補助テキスト用のグレー
- エラー・注意喚起用の色（`#FF9933` と役割が競合しないもの）。`/cautions` で使用する可能性がある

## 3.3 タイポグラフィ

| 用途 | 書体 | 入手先 | 備考 |
| --- | --- | --- | --- |
| 本文・見出し（プライマリ） | Kiwi Maru | Google Fonts | トンマナで指定。和風の字形で可読性が高い |
| 装飾（限定使用） | マキナス 4 Flat | 配布元より個別に入手 | Web フォントとしての利用可否を確認する必要がある |
| 装飾（限定使用） | 03スマートフォントUI | 同上 | 同上 |
| 装飾（限定使用） | はこべら角ゴシックA | 同上 | 同上 |

**注意事項:** 装飾用の3書体は Google Fonts に収録されていないため、Web フォントとして配信するにはライセンス条項の確認が必要である。確認が取れない場合、これらの書体は画像として書き出して使用する。**［要検討］**

**Figma 作業への影響:** ライセンスの確認が終わるまで、装飾書体を**ロゴおよびページ見出しの範囲に限定して使用する。** 本文・ナビゲーション・ボタンには使用しない。画像書き出しになった場合、テキストとして扱えない箇所（文字列の変更ができない、検索・読み上げの対象にならない）が生じるため、使用箇所が広いとやり直しの範囲が大きくなる。

## 3.4 レイアウト・グリッド

Figma の `01_Foundation` にレイアウトグリッドとして登録し、各アートボードに適用する。

| 項目 | 値 |
| --- | --- |
| 最大コンテンツ幅 | 1200px |
| グリッド | 12カラム（PC）／ 4カラム（モバイル） |
| ガター | 24px（PC）／ 16px（モバイル） |
| 外側余白 | 40px（PC）／ 16px（モバイル） |
| 間隔の基準単位 | 4px（4, 8, 12, 16, 24, 32, 48, 64, 96） |

**余白は上記の基準単位から選ぶ。** 中間の値（例: 20px、30px）を使用しない。Tailwind CSS の間隔指定と対応させるため、実装時に近い値へ丸められて意図とずれることを防ぐ。

## 3.5 ブレークポイント

Tailwind CSS の既定値を用いる。

| 名称 | 幅 | 主な対象 |
| --- | --- | --- |
| （既定） | 0px〜 | スマートフォン |
| `md` | 768px〜 | タブレット |
| `lg` | 1024px〜 | ノートPC |
| `xl` | 1280px〜 | デスクトップ |

Figma のアートボード幅は `375px` / `768px` / `1280px` の3種類を基本とする。

## 3.6 Figma のファイル構成

```text
第34回茨香祭 Web
├── 00_Cover              … 表紙、更新履歴、担当者
├── 01_Foundation         … カラー、タイポグラフィ、余白、グリッド
├── 02_Components         … 共通コンポーネント
├── 03_Wireframe          … 情報設計（配色なし）。17ページ分
├── 04_Design_Mobile      … 375px のデザイン
├── 05_Design_Desktop     … 1280px のデザイン
└── 99_Archive            … 不採用案の保管
```

**進め方の順序:** `01_Foundation` → `03_Wireframe` → `02_Components` → `04_Design_Mobile` → `05_Design_Desktop`。配色を決める前に情報の配置を確定させることで、修正の範囲を限定する。

各段階で作成するものと、着手前に決まっている必要がある事項を示す。

1. **`01_Foundation`** — カラースタイル（第3.2節）、テキストスタイル（第3.3.1節）、レイアウトグリッド（第3.4節）を登録する。本文書に値が記載されているため、着手できる。
2. **`03_Wireframe`** — 17ページの情報配置を配色なしで作成する。**着手前にナビゲーションの階層構造を決める必要がある**（17ページをヘッダーにどう収めるか。全ページ共通の要素であるため、後から変更すると全画面に影響する）。
3. **`02_Components`** — 第3.7節のコンポーネントを作成する。
4. **`04_Design_Mobile`** → **`05_Design_Desktop`** — モバイルを先に完成させる。第2.2節のとおりスマートフォンでの閲覧を第一の設計基準とするため。

**留意点:** 17ページのうち、`/about`、`/theme`、`/staff`、`/faq`、`/cautions` は文章が主体で構造が共通するため、1つのテンプレートで対応できる。個別にデザインを作成するのは、固有の構造を持つページに限る。

**`/circle/[slug]` は他のページより先に作成する。** このページは第2.8.2節のとおり HP と FesFlow の接続点であり、URL 形式（slug）の決定にも関わる。先に確定させることで、後続の判断材料になる。

## 3.7 作成するコンポーネント

`02_Components` に作成する。各コンポーネントは、記載のある状態（バリアント）をすべて作成する。状態を1つしか作らないと、実装時にその他の状態の見た目を実装者が判断することになる。

### 3.7.1 共通コンポーネント

| コンポーネント | 必要な状態 | 使用箇所 |
| --- | --- | --- |
| `Button/Primary` | 通常、hover、focus、無効 | 主要な操作 |
| `Button/FesFlow` | 通常、hover、focus | FesFlow への遷移。第3.2.2節の6により専用の配色 |
| `Link/Text` | 通常、hover、訪問済み、focus | 本文中のリンク。下線を併用する |
| `Header` | 通常、スクロール時 | 全ページ共通 |
| `Nav/Mobile` | 閉、開 | モバイルの開閉メニュー |
| `Nav/Desktop` | 通常、hover、現在地 | PC のナビゲーション |
| `Footer` | — | 全ページ共通 |
| `Card/Circle` | 通常、hover | `/circle` の一覧項目 |
| `Card/Event` | 通常、hover | `/event` の一覧項目 |
| `Card/News` | 通常、hover | `/news` の一覧項目 |
| `Tag/Category` | 通常、選択中 | カテゴリの表示と絞り込み |
| `Tab/Day` | 通常、選択中 | `/timetable` の日付切り替え |
| `Heading/Page` | — | 各ページ冒頭の見出し |
| `Image/Placeholder` | — | 画像が未提出の場合の代替表示 |

**`Image/Placeholder` を必ず作成する。** 第2.9.3節のとおり画像は任意項目であるため、画像のないサークルが存在する。代替表示がないと、実装時に空白のまま公開されるか、実装者が独自に用意することになる。

### 3.7.2 画面上の動作を伴う要素

以下は静止画のデザインだけでは実装できない。**動作前後の両方の状態を作成する。**

| 要素 | 該当ページ | 作成が必要な状態 |
| --- | --- | --- |
| モバイルメニューの開閉 | 全ページ | 閉じた状態、開いた状態 |
| タイムテーブルの日付切り替え | `/timetable` | 1日目を選択中、2日目を選択中 |
| カテゴリによる絞り込み | `/circle` | 絞り込みなし、絞り込み適用中、該当0件 |
| 会場マップの拡大 | `/map` | 初期表示、拡大時 |
| FesFlow リンクの有無 | `/circle/[slug]` | 導入サークル、未導入サークル（第2.8.2節） |

**FesFlow リンクの2状態は必ず両方作成する。** FesFlow の開発が HP の公開に間に合わない可能性があるため、リンクを表示しない状態のデザインがないと、その場合に表示するものがなくなる。

### 3.7.3 見落としやすい状態

各一覧ページには、**内容が存在しない状態**が発生する。開催前は特に該当する。

- `/news` — 公開前でお知らせが0件
- `/circle` `/event` — 原稿収集前で掲載が0件
- `/decoration` — 開催後に掲載する方針の場合、公開時点では0件（第2.8.9節）
- `/404` — 存在しないURLへのアクセス

これらのデザインを用意しない場合、実装時に空のページが表示される。少なくとも「準備中です」に相当する表示を1種類作成し、各ページで使い回す。

## 3.8 Figma の命名規則

| 対象 | 規則 | 例 |
| --- | --- | --- |
| ページ | `連番_英語名` | `04_Design_Mobile` |
| フレーム（画面） | `パス / ブレークポイント` | `circle-slug / 375` |
| コンポーネント | `分類/名称` | `Button/Primary` |
| バリアント | `プロパティ=値` | `state=hover` |
| カラースタイル | `役割/名称` | `color/accent` |
| テキストスタイル | `用途/サイズ` | `heading/h1-mobile` |

**規則:** 日本語と英語を混在させない。フレーム名は第2.7節のパスと一致させる。コンポーネント名はコーディング時のファイル名と一致させる（`Button/Primary` → `src/components/ButtonPrimary.astro`）。

## 3.9 デザインから実装への受け渡し

- デザインが完成したら Figma 上で「実装可」の注記を付け、対応する GitHub Issue にフレームへのリンクを記載する。
- **実装開始後のデザイン変更は、Issue を新規に作成してから行う。** Figma を直接書き換えるだけの変更を行わない。実装側が変更に気づけず、古いデザインのまま作業が進むため。

## 3.10 画像の扱い

| 項目 | 方針 |
| --- | --- |
| 形式 | 写真は WebP、図版は SVG を基本とする |
| 生成 | Astro の `<Image />` コンポーネントを用いて最適化する |
| ロゴ | SVG を使用。トンマナに従い、周囲にアイソレーションエリア（余白）を確保する |
| ロゴの禁止事項 | 地の色に対して濃く使用しない（白地に黒などの組み合わせを行わない）。雰囲気を損なう加工を行わない |
| ロゴの許可事項 | 色の変更、ネオンサイン風の加工 |
| サークル画像 | 縦横比を統一する。比率は ［未定］。原稿収集フォームで指定する |
| 会場マップ | SVG を推奨。拡大時に判読できるため |
| 代替テキスト | すべての画像に設定する。装飾目的の画像は `alt=""` とする |

## 付録B. デザイントークン定義（案）

Tailwind CSS の設定に記述する値の案。本章の確定後に更新する。

```css
@theme {
  /* Color */
  --color-base:    #0B3041;
  --color-text:    #E8E8E8;
  --color-main:    #FF9933;
  --color-accent:  #00FFCC;

  /* Font */
  --font-primary:  "Kiwi Maru", serif;

  /* Spacing (4px 基準) */
  --spacing-1:  4px;
  --spacing-2:  8px;
  --spacing-3:  12px;
  --spacing-4:  16px;
  --spacing-6:  24px;
  --spacing-8:  32px;
  --spacing-12: 48px;
  --spacing-16: 64px;
  --spacing-24: 96px;

  /* Layout */
  --container-max: 1200px;
}
```
